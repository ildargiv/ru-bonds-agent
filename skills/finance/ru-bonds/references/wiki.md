# База знаний: LLM-вики в формате Obsidian

Общий формат для всех агентов семейства: ru-stocks-agent (акции), ru-portfolio-agent (семейный офис),
ru-bonds-agent (облигации), finex-agent (ликвидация FinEx). Файл одинаковый во всех четырёх репозиториях,
как и скрипт `scripts/wiki.py`, поэтому хранилища разных агентов открываются в одном Obsidian.

## Зачем
Агент не должен каждый раз собирать знания с нуля. Всё, что он прочитал и понял, оседает в markdown-заметках
со ссылками `[[...]]`. Следующий разбор начинается с чтения вики, а не с поиска в интернете. Пользователь
видит ту же базу в Obsidian: граф связей, обратные ссылки, свойства, поиск, правит руками.

## Три слоя
1. **Сырые источники** (неизменяемые, только пополняются): PDF и тексты отчётов, документы ликвидаторов,
   `news.jsonl`, `prices.csv`, `snapshots.jsonl`, срезы форумов. Агент их не переписывает.
2. **Вики** (пишет агент): хаб-заметка на бумагу или фонд, профиль, тезис, разборы, конспекты отчётов,
   проверенные новости, темы, эмитенты, решения, дайджесты, `index.md`, `log.md`.
3. **Схема** (этот файл): структура, frontmatter, правила ссылок и источников, операции.

## Где лежит
| Агент | Хранилище (переменная) | Внутри общего хранилища `INVEST_VAULT` |
|---|---|---|
| ru-stocks-agent | `~/stocks-desk` (`STOCKS_DESK`) | `INVEST_VAULT/stocks/` |
| ru-portfolio-agent | `~/family-office` (`FAMILY_OFFICE`) | `INVEST_VAULT/stocks/` (общие папки бумаг с акциями) |
| ru-bonds-agent | `~/bonds-desk` (`BONDS_DESK`) | `INVEST_VAULT/bonds/` |
| finex-agent | `~/finex-desk` (`FINEX_DESK`) | `INVEST_VAULT/finex/` |

- Отдельно: откройте папку хранилища агента в Obsidian («Открыть папку как хранилище»).
- **Всё в одном Obsidian:** задайте всем агентам `INVEST_VAULT=~/invest-vault` (и не задавайте отдельные
  переменные) — у каждого агента будет своя подпапка, а `Home.md`, `topics/`, `_templates/`, `.obsidian/`
  окажутся общими в корне. Откройте в Obsidian сам `~/invest-vault`. Агенты акций и портфеля пишут в одни
  и те же папки бумаг, так что заметка про SBER одна.
- Уже есть данные в старом месте — перенесите папку в `INVEST_VAULT/<подпапка>` и запустите `wiki.py sync`.

## Frontmatter (свойства Obsidian)
Каждая заметка начинается с YAML. Обязательно `type`; остальное — по типу.

| type | Где | Ключевые поля |
|---|---|---|
| `security` / `bond` / `fund` | хаб бумаги | `id`, `ticker`, `isin`, `name`, `issuer`, `inn`, `status`, `verdict`, `score`, `target`, `last_analysis`; фонд — `nav`, `nav_date`, `quote` |
| `issuer` | `issuers/` (облигации) | `name`, `inn` |
| `profile`, `thesis`, `journal`, `financials`, `news-log` | файлы в папке бумаги | `entity`, `up` |
| `analysis` | `analyses/` | `entity`, `date`, `verdict`, `score`, `target` |
| `report` | `reports/*.md` | `entity`, `date`, `period`, `doc_kind`, `source` (URL) |
| `source` | `sources/`, `docs/` | `date`, `source`, `status` |
| `news` | `news/<дата>-….md` | `entity`, `date`, `source`, `status` (✅/⚠️/💬/❌) |
| `topic` | `topics/` | `entities: [SBER, LKOH]`, `source` |
| `decision` | `decisions/` | `entity`, `date`, `status` |
| `digest`, `index`, `log`, `lint`, `home` | служебные | `week` / `desk` |

Общие поля: `up: "[[SBER/SBER|SBER]]"` (ссылка на хаб — связывает граф), `tags: [desk/stocks, type/thesis]`,
`created`, `updated`, `agent` (кто создал), `private: true` (личное). Хаб-заметки и index собирает
`wiki.py sync` из данных хранилища — не правьте их свойства руками, пишите в раздел «Заметки».

## Ссылки
- На бумагу — `[[SBER/SBER|SBER]]`, на её файл — `[[SBER/thesis|тезис]]`, на тему — `[[topics/Ключевая ставка ЦБ]]`.
  Путь с папкой однозначен и в отдельном, и в общем хранилище.
- На вложение — `[[SBER/reports/2026-9m-ifrs.pdf|PDF]]`, встроить — `![[...pdf#page=4]]`.
- В таблицах разделитель экранируется: `[[SBER/SBER\|SBER]]`.

## Источники — у каждой цифры
- Формат: `… 1 234 млрд ₽ ([[SBER/reports/2026-9m-ifrs|МСФО 9м26]], стр. 4)` или `… (cbr.ru, 2026-11-01)`.
- Таблицы — со столбцом «Источник». Факт без источника — гипотеза, помечай ⚠️.
- Новости и форумы: статусы ✅ подтверждено первоисточником / ⚠️ частично / 💬 слух / ❌ опровергнуто.
- Проверяемые факты удобно писать полями `ключ:: значение (источник, дата)` — их видит Dataview, а
  `wiki.py lint` ищет по ним противоречия между заметками одной бумаги.

## Авто-блоки
Хабы, заметки отчётов и документов, index, Home и дайджесты содержат блок между
`<!-- wiki:auto:start … -->` и `<!-- wiki:auto:end -->`. Его пересобирает `wiki.py sync`. Всё, что ниже или
выше блока, — ваше и агента, скрипт это не трогает. Заглушка `_Агент: …_` значит «здесь нужен текст».

## Операции
| Операция | Как |
|---|---|
| **Перед работой (query)** | Прочитать хаб бумаги, затем по ссылкам тезис, последний разбор, конспекты отчётов. `wiki.py find "<что ищем>" [--entity X] [--type T]` — что уже известно, прежде чем искать в интернете |
| **Приём источника (ingest)** | Сохранить сырой файл (скрипты агента делают это сами) → `wiki.py sync` создаст заметку-конспект → заполнить «Конспект» с номерами страниц → обновить затронутые заметки (тезис, профиль, темы) → строка в `log.md` |
| **Записать знание** | `wiki.py log "<что узнали>" --entity X --kind факт|вывод|поправка|источник|тезис|решение|вопрос --source "<откуда>"` — одна строка на факт |
| **Новая заметка** | `wiki.py note topic|source|news|decision|analysis|issuer "<заголовок>" [--entity X] [--source URL]` |
| **После работы** | `wiki.py sync` (скрипты агента вызывают его сами после add/analysed/log/архивации отчёта) |
| **Проверка (lint)** | `wiki.py lint --save` — битые ссылки, заметки без frontmatter, цифры без источника, сироты, устаревшие тезисы и темы (> 90 дн.), незаконспектированные отчёты и документы, противоречия (поле с разными значениями в разных заметках; тезис против итога комитета; валюта СЧА против валюты фонда). Противоречие разбирай по первоисточнику и пиши итог в `log.md` с видом «поправка» |
| **Недельный дайджест** | `wiki.py digest` → дописать «Выводы недели» → коротко пользователю |

## Правила
- **Вики — первая память.** Перед вопросом в интернет загляни в вики; после — запиши найденное в вики.
- **История не переписывается**: `journal.md`, `analyses/`, `log.md`, `digests/`, сырые файлы — только пополняются.
  Текущие документы (профиль, тезис, темы, хабы) — перезаписываются, старое значение остаётся в разборах и log.
- **Одна мысль — одно место.** Факт про отрасль или ставку — в `topics/`, у бумаги — ссылка на тему.
- **Личные данные не попадают в вики.** Количества, суммы позиций, средние цены, номера счетов, пересланные
  сообщения из закрытых групп живут только в `portfolio.json`, `_portfolio/`, `inbox/` (они в `.gitignore`
  хранилища). В заметках про бумаги — только публичные факты и выводы.
- **Obsidian не обязателен.** Это обычные markdown-файлы: их читают Hermes, OpenClaw, Claude Code, Codex и
  любой редактор. Плагины Dataview, Templater, Folder Notes — по желанию.
